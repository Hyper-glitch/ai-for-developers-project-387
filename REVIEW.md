# Ревью календаря звонков

Сверь изменение с исходным обращением, критериями спецификации, связанными тикетами и комментарием, в котором человек согласовал объём. Сравни автора и ссылку согласования с данными GitHub. Если ссылки, части diff или результаты проверок недоступны, назови пробел и объясни, какое утверждение он мешает проверить. Отдельно укажи изменения за пределами согласованной задачи.

## Поведение календаря

- Один владелец принимает встречи всех типов. После бронирования пересекающийся слот исчезает для каждого типа. Попытка занять его повторно возвращает 409 и сохраняет исходное бронирование. Встречи встык допустимы.
- Слот целиком входит в рабочие часы. Дата, начало дня и границы окна записи зависят от часового пояса владельца. В списке предстоящих бронирований видна уже начавшаяся встреча до её окончания.
- Проверь основной путь и соседний случай из спецификации. Для каждого действия в разделе владельца проверь, к какому гостю и бронированию оно относится, в том числе при двух карточках на экране. Учитывай пустой список.
- При изменении API проверь TypeSpec, OpenAPI, модели и SDK. При изменении формы проверь принятие и отклонение ввода и видимое гостю поведение после отказа.

## Проверки и риск

Соотнеси последствия ошибки с проверками в PR. Для подписи важен видимый текст, для слотов — пересечение разных типов и границы интервалов. Для GitHub Actions проверь, какой код исполняется с секретами, как проверяются автор и ветка и куда токен может писать. Такое изменение требует отдельного решения человека.

Проверь ожидаемый отказ на базе и успех на head, ссылку на CI, фактический SHA браузерной проверки и план отката, включая судьбу записанных данных. Укажи статусы, которые ещё выполняются. Итоговый ответ о ревью принимает человек после сверки актуального SHA и артефакта.

## Ответ ревьюера

Для каждого подтверждённого дефекта укажи путь и строку на проверяемой версии (для удаления уточни сторону diff), воспроизводимые условия и видимое последствие. Отдели недостающие свидетельства от дефектов. При повторном ревью сверь изменения с предыдущими замечаниями и ответами человека. Если подтверждённых дефектов нет, прямо напиши об этом. Оформление проверяет линтер. Ответ дай на русском.
